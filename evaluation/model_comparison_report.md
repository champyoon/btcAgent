## 0. 전제 변경

이전까지는 "제출 모델 = Sonnet 4.5"를 고정 전제로 두고, 쿼터가 막히면 Haiku로 임시 대체했다가 복구되면
되돌리는 방식으로 작업했다. 사용자가 이 전제를 해제하고 "Bedrock에서 실제 쓸 수 있는 모델과 쿼터를 확인한
뒤, 답변 품질·속도·비용을 근거로 후보를 비교해 추천하라"고 요청함에 따라, 이 문서에서 그 비교를 수행하고
**Haiku 4.5를 최종 제출 모델로 채택**했다(근거는 §4). `src/agent.py:MODEL_ID`도 이 문서 작성과 함께
`us.anthropic.claude-haiku-4-5-20251001-v1:0`로 확정 변경했다 — 더 이상 "임시 대체"가 아니라 최종 선택이다.

## 1. 이 Bedrock 계정에서 실제 확인된 모델·쿼터 상태

`list_inference_profiles` 호출로 이 계정에 75개의 추론 프로파일이 있음을 확인했다(Claude 3
Sonnet/Haiku, Sonnet 4/4.5/4.6/5, Opus 4.1/4.5/4.6/4.7/4.8/5, Haiku 4.5, Fable 5/5.1, Nova
Premier/Micro/Lite/Pro/2-Lite, 각각 `us.`/`global.` 접두사). 그중 실제로 `.invoke()`를 시도해 응답 여부를
직접 확인한 모델과 상태:

| 모델 | 상태 | 비고 |
|---|---|---|
| `claude-haiku-4-5` | **정상 동작** | — |
| `claude-sonnet-4-5` | **미평가(쿼터 소진)** — 품질 문제 아님 | `ThrottlingException: Too many tokens per day` — 일일 토큰 쿼터 소진으로 응답 자체를 받지 못함. 한 번 복구되어 RAGAS 8건 중 2건 성공(`rag_eval_results_sonnet_partial_20260917.json`) 후 다시 소진됨 |
| `claude-sonnet-4-6` | **미평가(쿼터 소진)** — 품질 문제 아님 | 동일 `ThrottlingException: Too many tokens per day`. 이번 비교 실행(§3)에서 3문항 모두 이 오류로 응답 자체를 받지 못함 — Sonnet 계열이 쿼터 풀을 공유하거나 이 계정 자체의 Sonnet 티어 한도가 낮은 것으로 보인다 |
| `claude-sonnet-5` | 권한 없음 | `AccessDeniedException` — 모델 접근 권한 없음 |
| `claude-opus-5` (및 4.1/4.5/4.6/4.7/4.8) | 권한 없음 | `AccessDeniedException` |
| `claude-fable-5`, `claude-fable-5-1` | 권한 없음 | `AccessDeniedException` |
| `claude-sonnet-4-20250514` | 권한 없음 | `AccessDeniedException` |
| `amazon.nova-pro-v1:0` | **정상 동작** | — (도구 호출 포함, `langchain_aws.ChatBedrockConverse.bind_tools()`로 정상 변환됨 — CLAUDE.md에 남아 있던 "Nova는 도구 호출 미검증" 캐비아트는 이 확인으로 해소) |
| `amazon.nova-lite-v1:0` | 부분 동작 — **실제 결함** | 도구 호출 자체는 되지만 §3에서 실제 결함(잘못된 도구 선택 + 필수 인자 누락으로 크래시) 발견 |

**Sonnet 4.5/4.6은 "품질이 낮아서 탈락"이 아니라 "이 계정에서 쿼터가 상시 소진돼 응답 자체를 받을 수
없어서 평가가 불가능했다"는 뜻이다** — 이 문서와 하위 문서 전체에서 Sonnet 관련 결과는 이 의미로만
읽어야 한다.

**쿼터 부족(Throttling)과 권한 부족(AccessDenied)은 명확히 다른 문제**다 — 전자는 시간이 지나면(또는 한도
상향 요청으로) 풀리는 반면, 후자는 AWS 콘솔에서 해당 IAM 사용자/계정에 모델 접근을 명시적으로 활성화해야
한다(Bedrock → Model access). **`sonnet-5`/`opus-4.1~5`/`fable-5`/`fable-5-1`을 후보로 쓰려면 이 권한을
먼저 요청해야 하고, 이는 내가 대신 할 수 없다** — 사용자가 AWS 콘솔에서 직접 처리해야 하는 항목이다.

## 2. 비교 방법

동일한 격리 상태(예산 200만원, 다음 달 RSI 전략 선택+확정 완료)에서 4개 후보 모델(`haiku-4-5`,
`sonnet-4-6`, `nova-pro`, `nova-lite`) 각각에 대해 `agent.build_supervisor(llm=<후보 모델>)`로 슈퍼바이저를
새로 빌드하고, 동일한 3개 대표 질문을 순서대로 보냈다(호출 간 6초 간격):

1. **개인 상태 vs 일반 설명 구분**: "다음 달 전략 뭐야?" — `plan_agent`가 실제 상태를, `research_agent`가
   일반 규칙만 답하고 실제 상태 판단은 위임하는지 확인.
2. **정확한 도구 선택**: "하락일 매수 조건이 뭐야?" — 개념 질문이므로 `research_agent`가 문서 근거로
   정확한 조건을 답해야 하고, `plan_agent`가 근거 없이 조건을 지어내지 않아야 함.
3. **근거 충실도**: "RSI가 낮으면 반드시 오르는가?" — 단정("반드시 오른다")을 부정하고 후행지표 한계를
   문서/데이터 근거로 설명하는지 확인.

sonnet-4-5/sonnet-5/opus-5/fable-5류는 §1의 사유로 이 비교에서 제외했다(각각 별도 기록).

## 3. 모델별 결과

### haiku-4-5 — 3/3 성공, 결함 없음

| 질문 | 소요시간 | 결과 |
|---|---|---|
| Q1 상태구분 | 7.4s | `plan_agent`: "다음 달(2026년 10월)의 전략은 **RSI**"라며 실제 값을 답함. `research_agent`: "실제 현재 상태는... 다른 Agent가 실시간으로 확인해드릴 수 있습니다"라며 역할을 정확히 위임 — 모순 없음 |
| Q2 도구선택 | 13.0s | `plan_agent`: "도구가 없어 근거 없이 답하면 실제 규칙과 다를 수 있기 때문입니다(예: 과거에 '전일 대비 하락'이라고 잘못 답한 적이 있는데...)"라며 스스로 답변을 거부하고 위임. `research_agent`가 정확한 두 조건(당일 시가 대비 -5% AND 월 첫 매수가 미만)을 정확히 설명 |
| Q3 근거충실도 | 10.3s | `price_agent`/`research_agent` 모두 "반드시 오르지 않는다"를 후행지표·추세 지속 가능성 등 구체적 근거로 설명 |

세 응답 모두 서식이 깔끔하고(빈 줄 아티팩트 없음), 역할 경계·근거 인용이 가장 정확했다.

### sonnet-4-6 — 3문항 전부 미평가(쿼터 소진, 품질 문제 아님)

3문항 모두 `ThrottlingException: Too many tokens per day`(15.6s/13.0s/9.1s 재시도 후에도 응답을 받지
못함)로 **응답 자체를 받지 못해 품질을 평가할 수 없었다**. 이 계정에서는 일일 토큰 쿼터가 상시
소진돼 있어 사실상 사용 불가능한 상태이고, 이는 모델의 답변 품질과는 무관한 계정/쿼터 문제다.

### nova-pro — 3/3 성공, 경미한 품질 저하

| 질문 | 소요시간 | 결과 |
|---|---|---|
| Q1 | 6.0s | `plan_agent` 정답. `research_agent`는 "관련 문서를 찾지 못했습니다"로 답했는데, 모순되는 상태 주장은 하지 않아 안전하게 실패했지만 정보성은 낮음 |
| Q2 | 6.1s | `plan_agent` 응답이 "정확한 조건은 문서 검색 결과를 참고하세요." 한 줄뿐으로 haiku 대비 설명이 빈약함(앞에 빈 줄 아티팩트 있음). `research_agent`는 정확한 조건을 답함 |
| Q3 | 9.3s | `price_agent`가 실시간 `get_indicators`(RSI 50.80, 중립 구간)를 근거로 답변 — 라이브 데이터 활용은 haiku보다 구체적이었음. `research_agent`도 정확 |

Haiku보다 빠르지만(6.0/6.1/9.3s), 일부 응답이 haiku보다 짧고 설명력이 떨어졌다. 결함이라 부를 정도는
아니지만 품질 편차가 있다.

### nova-lite — 1/3 실패(실제 결함), 나머지 2건도 서식 문제

**Q1에서 실제 결함 발생**: "다음 달 전략 뭐야?"라는 조회성 질문에 대해 잘못된 도구(`select_strategy` —
전략을 **변경**하는 쓰기 도구)를 호출했고, 그마저도 필수 인자 `strategy`를 채우지 못해 Pydantic
`ValidationError`로 요청 전체가 크래시했다:

```
ValidationError: 1 validation error for select_strategy
strategy
  Field required [type=missing, input_value={'month': 10, 'year': 2026}, input_type=dict]
```

이는 이중 결함이다 — (a) 조회 질문에 변경 도구를 선택한 **도구 선택 오류**, (b) 그 호출조차 필수 인자
없이 시도해 **예외로 전체 요청이 중단**됨(우리 쪽 "절대 raise하지 않는다" 컨벤션이 적용되는 도메인 함수
호출 이전 단계, 즉 LLM 도구 호출 인자 파싱 단계에서 터지므로 서버 쪽에서 잡을 수 없는 크래시). 서비스
관점에서 흔한 질문 하나가 사용자에게 500 에러로 보일 수 있는 심각한 신뢰성 문제다.

Q2/Q3는 내용은 정확했지만(하락일 조건, RSI 후행지표 설명 모두 정답) 응답 앞에 빈 줄이 2~3개씩 붙는
서식 아티팩트가 매 응답에 나타났다.

## 4. 결론 및 추천: Haiku 4.5

| 기준 | haiku-4-5 | nova-pro | nova-lite | sonnet-4-6 |
|---|---|---|---|---|
| 개인상태/일반설명 구분 | 정확 | 정확(단, 정보성 낮은 응답 1건) | 정확(서식 문제) | 미평가(쿼터) |
| 정확한 도구 선택 | 정확 | 정확 | **오류 발생(크래시)** | 미평가(쿼터) |
| 근거 충실도 | 높음, 구체적 | 보통(일부 짧음), 라이브 지표 활용 우수 | 보통 | 미평가(쿼터) |
| 응답 속도 | 7.4~13.0s | 6.0~9.3s (가장 빠름) | 2.8~5.8s | 미평가(쿼터) |
| 이 계정에서의 가용성 | **안정** | 안정 | 안정(단, 품질 결함) | **미평가 — 쿼터 상시 소진, 품질 문제 아님** |

**Haiku 4.5를 최종 제출 모델로 추천한다.** 이유:
- 3개 대표 질문 모두 결함 없이 통과한 유일한 모델이고, 역할 경계·근거 제시가 가장 정확하고 설명력이 좋다.
- Sonnet 계열(4.5/4.6)은 이 계정에서 반복적으로 일일 토큰 쿼터가 소진되어 **품질과 무관하게 안정적으로
  쓸 수 없다** — 서비스 신뢰성 관점에서 채택하기 어렵다.
- Nova-lite는 흔한 질문 하나에서 실제 크래시(도구 선택 오류 + 필수 인자 누락)를 냈다 — 저비용이지만
  이 상태로는 채택할 수 없다.
- Nova-pro는 결함 없이 동작하고 haiku보다 빨랐지만, 응답 품질(설명 길이/구체성)이 다소 떨어지는 편차를
  보였다. 만약 응답 속도나 비용이 haiku보다 훨씬 중요하다면 **차선책**으로 고려할 만하다.
- Anthropic 계열 내에서 Haiku는 통상 Sonnet보다 토큰당 단가가 낮은 저비용 티어로 알려져 있고, 이번
  비교에서도 유일하게 쿼터·품질 모두 안정적이었다는 점에서 **비용까지 고려해도 품질/속도/비용 세 기준
  모두 상대적으로 유리한 선택**이다. 다만 AWS Bedrock 콘솔의 정확한 실시간 단가(원/1K 토큰)는 이 세션에서
  프로그래밍적으로 확인하지 못했다(정적 페이지 크롤링 시도 2회 모두 실패 — 페이지가 JS로 렌더링되어
  단가 표를 가져오지 못함). **정확한 단가가 필요하면 AWS Bedrock 콘솔 pricing 페이지를 직접 확인하는
  것을 권장**하며, 이 문서는 "안정성·품질에서 haiku가 명확히 우위"라는 근거로 추천하는 것이지 정밀한
  비용 수치를 근거로 하지 않는다.

## 5. 추가 권한/비용 승인이 필요한 항목 (사용자 조치 필요)

- `claude-sonnet-5`, `claude-opus-4.1~5`, `claude-fable-5`, `claude-fable-5-1`: 전부
  `AccessDeniedException` — AWS Bedrock 콘솔의 Model access에서 이 IAM 사용자/계정에 대해 명시적으로
  활성화해야 사용 가능하다. 내가 대신 처리할 수 없다.
- `claude-sonnet-4-5`/`claude-sonnet-4-6`: 권한은 있으나 이 계정의 일일 토큰 쿼터가 상시 소진 상태다.
  더 높은 한도가 필요하면 AWS Support를 통한 Service Quota 상향 요청이 별도로 필요하다(비용에 영향).
- 위 항목 모두 **이번 최종 선택(Haiku 4.5)에는 필요하지 않다** — Haiku는 이미 정상 동작 확인된 모델이며
  추가 권한이나 비용 승인 없이 바로 사용 가능하다.

## 6. 참고: 이번 비교와 별개로 확인된 사항

Nova 계열의 도구 호출(tool-calling) 호환성은 `ChatBedrockConverse.bind_tools()`로 정상 동작함을 이번에
직접 확인했다(nova-pro/nova-lite 둘 다 도구를 호출은 함 — 다만 nova-lite는 인자 채우기에서 실패). 이전
CLAUDE.md에 남아있던 "Nova는 도구 호출 방식이 달라 미검증"이라는 캐비아트는 이 확인으로 해소하고, 대신
nova-lite의 구체적 실패 사례(§3)로 갱신했다.
